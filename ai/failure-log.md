# Failure log

Every time an agent (build-time or runtime) failed, stalled or produced something
wrong, it is recorded here: what happened, how it was detected, how we
recovered, and what changed in the harness so it does not recur.

| Id | Stage | Symptom | Detection | Recovery | Harness change |
|---|---|---|---|---|---|
| F-001 | Setup | Agent tried to create the Python venv and failed with `Operation not permitted` | Shell exit code + error text | Re-ran with explicit elevated permission for that one command | `AGENTS.md` "Commands" section now documents `make setup` as the single setup entry point so agents do not improvise |
| F-007 | Operations (docs) | AI-written docs drifted from the code: the architecture doc and README draft cited `raw/graph/context.py` (never existed; the pack is `context_pack()` in `services/assessment.py`) and a "~1.5k token" pack (measured: ~150); the runbook said restarting the API re-ingests edited policies (startup only ingests into an empty corpus); the README said citations open on hover (they open on click) | Grepping every path, function and number in the README, deck and runbook against the code before the final commit; the screenshot rehearsal script failing on the hover step | Corrected the docs; added `scripts/reingest.py` so the runbook step is real | Reviewer rule 10: every file path, command and number in docs must be checked against the code or a generated artefact. `npm run screenshots` rehearses the demo and fails if a step's UI state is missing |
| F-006 | Operations | Token report's first draft claimed a passages-per-dimension saving that was never measured | Reading the generated report against the ledger query that produced it | Removed the claim; caveats added for offline-mode critic and small golden briefs | Report text is generated only from ledger numbers (`ops/token_report.py`); no hand-written figures |
| F-005 | Testing | Lifecycle API test asserted the second-analyst ack path only `if o["requires_ack"]`, so it could pass without ever exercising US-08 (AI-written test with a conditional that hid the case it was meant to prove) | Reviewing the tests line by line against the user stories, not just the green result | Assertion made unconditional with an override (TPV 5x5) that must change the tier; seed data now includes a tier-changing override so the demo shows a pending ack | Reviewer rule in `ai/agents/reviewer.md`: no conditional asserts around the behaviour a test is named for |
| F-004 | Evals | Held-out synthetic set showed extraction list F1 0.962 while golden showed 0.982. "high-net-worth individuals" added `retail`, and product name "corporate payments" added `corporate` customers - both invisible on the golden set the extractor had been debugged against | `evals/run_evals.py --dataset data/synthetic/change_requests.jsonl` (held-out set) | Scrub regex removes phrases already claimed by a more specific meaning before customer-type keywords are scanned | Held-out set kept out of tuning; every extractor change is run against both sets |
| F-003 | Development (runtime harness) | All API tests passed on first run, but inspecting golden case G01 showed residual tier High where the golden label is Medium. Root causes in the deterministic extractor: "platform companies" matched the `corporate` keyword (false customer type), and a controls sentence that wrapped onto a second line was cut, so the velocity limit never mapped to C-LIM-01 and Products risk kept zero mitigation | Human inspection of the full assessment dump (`RAW_INSPECT=1 pytest tests/api/test_inspect_output.py`) against the golden facts - green tests were not trusted on their own | Removed the over-broad keyword; sentence splitter now joins line-wraps within a paragraph; control phrases split on `,`/`;` only (not inside numbers like `2,000`) | Added the inspection helper to the workflow and made golden-set evals (extraction F1 + tier agreement) a CI gate so this class of error is caught by numbers, not by luck |
| F-002 | Setup | `git` unavailable on the build Mac (Xcode Command Line Tools missing) - agent could not commit, and commit history is a judged artefact | `xcode-select` error on first `git status` | Triggered CLT install for the human; agent committed through `dulwich` (pure-Python git, standard `.git` format) until native git was available | Setup checklist in README lists git as a prerequisite |
